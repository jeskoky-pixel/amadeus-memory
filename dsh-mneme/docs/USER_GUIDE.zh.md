# Amadeus Memory 普通用户指南

## 打开设置

DSH Desktop → **设置** → 左侧 **Amadeus 记忆**（英文界面为 **Amadeus Memory**）。

这个页面提供日常记忆管理、常用配置、Embedding、偏好以及安全备份/恢复；复杂的知识图谱、别名合并、审计、维护仍在原 **Memory** 面板。页面底部有 **打开完整记忆管理**。

## 日常记忆管理

- 搜索框按标题/正文做关键词搜索，可切换“显示归档”。
- **新建记忆**：选择类型、标题、正文、重要度 1–5 和标签；标签用英文逗号分隔。
- 每条记忆可以 **编辑**、**归档/取消归档**、**删除**。
- 编辑使用 `updated_at` 乐观并发检查；如果另一个页面先改了同一条，保存会提示“已被其他页面修改”，不会静默覆盖。重新打开即可拿到最新内容。
- 删除需要二次确认；删除不可撤销。高价值记忆请先创建备份。
- 事件标签（`event:*`）只能由受信 intake 生成，普通编辑器不会伪造。
- 列表分页为每页 20 条；窄窗口下按钮自动换行，不会横向溢出。

## 备份与恢复

- **创建备份**：生成当前 SQLite 的一致性快照，保存到 `memoryDir/backups/`；不会中断使用。
- **校验**：只读执行 SQLite `quick_check`、检查 `memories` 表和 SHA-256。
- **暂存恢复**：勾选“我了解需要重启并确认恢复”后暂存；运行中的数据库不会被覆盖。重启 DSH 后，Memory 在打开数据库前先自动保留 `pre-restore-*` 现场，再应用备份。
- 恢复前如果备份损坏、checksum 不符或表缺失，会保留当前数据库并明确报错；不会启动空库。
- 回滚使用自动保留的 `pre-restore-*` 目录；不要删除现场。
- 恢复默认参数只重置参数，不删除记忆；重置偏好只清空权重，不删除记忆。

## 运行概览

页面顶部显示：

- 记忆总数、活跃数、归档数、遗忘数；
- SQLite 快速检查结果与日志模式；
- 自动整理是否在运行；
- 最近一次自动巩固（autoDream）和 Sleep 时间；
- 当前 Embedding Provider、模型、维度与向量索引覆盖；
- 版本与设置页读取状态。

“向量不可用”不等于记忆丢失：关键词检索仍可使用。若 Provider 未配置、初始化中或网络失败，页面会如实显示，不会伪装成正常。

## 自动记忆与整理

常用开关：

- **自动注入旧记忆**：每轮是否把相关记忆带进上下文。
- **会话自动总结**：会话结束后是否自动提炼。
- **后台自动整理（autoDream）**：合并、去重和整理记忆。
- **Sleep Mode**：长时间空闲时做深度维护。
- **偏好权重参与检索**：启用 Tag/实体权重重排。
- **受信经历写入**：允许受控的 Life/外部入口写入带 provenance 的经历；普通聊天不能伪造完成事件。
- **实体抽取**：从记忆中抽取人物/项目/关系。
- **结果重排**：对检索结果再做一次精排。

这些开关与原 Memory 设置页使用同一份运行时覆盖。保存后如果提示“重载插件后生效”，按提示重载；不会静默假装已经生效。

## 注入与记忆参数

这一组使用 DSH Config Forms，和 Plugin Manager 的配置同源：

- 记忆语言；
- 触发自动巩固的条数/字符数与延迟；
- Sleep 空闲分钟数；
- 每轮最多注入条数；
- 自动注入重要性门槛；
- 单条注入正文截断长度；
- 注入跨轮轮换；
- 向量候选数、相似度阈值、混合检索权重；
- 启动时是否自动补齐缺失向量。

保存前会做范围校验；保存后页面提示插件重载。恢复默认只恢复这些参数，不删除记忆。

## Embedding 与真实连通性测试

- **Provider**：OpenAI 兼容、本地 ONNX 或 Ollama。
- **OpenAI 兼容**：可编辑 Base URL、模型和 API Key。页面只显示“已配置”与掩码；留空或保持掩码表示保留现有密钥，升级不会要求重填仍有效的 Qwen3-Embedding-8B 密钥。
- **本地 ONNX / Ollama**：显示当前模型与维度；模型/地址沿用既有运行时配置。
- **测试连通性**：只有点击按钮才会发起请求。远端 Provider 会产生一次真实 API 请求，页面会先提示。
- 修改 Provider 或模型可能导致既有向量索引失配，需要重建索引；保存提示会说明需要重载。

## Tag 与实体偏好

- 查看、增加、修改或删除 Tag 权重（0.5–2.0，默认 1.0）。
- 查看、增加、修改或删除实体权重；实体可以输入 UUID 或唯一名称。
- 同名多实体时不会猜测，页面会列出候选，必须选择具体 UUID。
- **恢复默认权重** 只清空偏好权重，不删除任何记忆。按钮需要二次确认。

偏好总开关在“自动记忆与整理”里；关闭或所有权重为 1.0 时检索行为保持不变。

## 打开完整记忆管理

点击 **打开完整记忆管理** 会打开既有 Memory 面板。若 DSH 设置窗口仍覆盖在其上，先关闭设置窗口，或使用侧边栏的 Memory 入口。

完整面板继续提供：

- 记忆搜索、筛选、编辑、归档/遗忘；
- 知识图谱与实体详情；
- 别名确认、外部标识、规范合并/撤销；
- 权重候选、审计和存储维护；
- 模型工具与向量诊断。

## 安全与隐私

- 设置页数据接口要求同一来源并解析为 DSH 已认证 owner；不是“本机端口即管理员”。
- API Key 不返回浏览器；只返回是否已配置与掩码。
- 记忆正文只在已认证 owner 打开编辑/列表时返回给当前设置页；不导出到日志、备份元数据或第三方。
- 高风险删除、恢复需要二次确认；恢复只在重启后应用。
- 不要把隔离验收 Profile 指向生产记忆库；生产升级前先备份。

## 常见问题

**开关保存了但行为没变？** 查看页面是否提示“重载插件后生效”；功能开关和结构配置都需要 Host 重新读取。不要重复点击或直接改 SQLite。

**向量检索不可用？** 先看 Provider/模型/密钥是否完整，再看索引覆盖和初始化状态；关键词检索仍可用。

**页面打不开或报 503/403？** 检查插件是否启用、DSH 版本是否支持 `configForms`/Connection owner 鉴权，以及是否从同一 DSH 页面访问。

**迁移后需要重填密钥吗？** 不需要。同包名、同插件 ID、同 `memoryDir` 和同 `vector` 设置会继承；页面只显示掩码。若确实没有继承，先停止操作并检查是否误用了另一个 Profile。
