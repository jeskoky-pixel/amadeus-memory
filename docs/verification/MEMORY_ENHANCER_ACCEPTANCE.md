# Amadeus Memory Enhancer — Codex 验收

2026-10-25。开发分支：`codex/memory-enhancer`。基线：Mneme 上游 `146fa3657dbb73c0498aba969977e7c14e13684a`，导入提交 `13e6520`。本次仅修改独立开发工作树；生产插件、DSH 主配置和生产 SQLite 未切换或写入。

## 已验收的行为

- 稳定身份以 `(platform, entity_type, external_id)` 为键。同一平台、同一类型的不同 ID 即使昵称相同，也保持独立；同一 ID 更名仍解析到原 UUID。没有可靠 ID 的人物或群组不能只凭名称自动归并。
- 跨平台同类型实体默认独立，可由用户查看 dry-run 报告后手动确认关联。人物与群组不能合并；相同平台和数字 ID 在不同类型下可以分别存在。
- 旧库的确定性 QQ 群号可识别旧提取器标为 `organization` 的实体。迁移把这类实体类型修正为 `group`，把原类型写入审计证据；一个群号只建立一个有效外部身份键，重复行留作人工确认候选，不自动合并。
- 合并只建立可撤销的规范链接。确认前在写事务内重新计算属性、关系、身份、别名和阻断条件的指纹；原记忆、实体属性时间线及关系来源和权重不因合并改写。
- Tag 与实体偏好作为独立且有上限的排序信号；默认关闭或全为 1.0 时保持旧检索结果。可信经历入口要求明确来源、参与状态和 scope。
- 新的身份、偏好及经历来源接口要求服务端实际配置 `apiToken`；旧开放目录和图谱接口只返回脱敏的原有字段。开放目录搜索、图谱查询、`entity:` 搜索和普通搜索的图谱召回都只用公开名称或 UUID，不能通过查询探测私人别名或外部 ID。实体目录支持分页、搜索和真实总数，原生面板可继续加载后续实体。

## 检索与运行成本

Codex 在最终代码上复跑同一合成基准（50 条记忆、3 个查询、3 轮、每轮 20 次）：Recall@5 `0.3333 → 0.8492`，MRR `0.3333 → 1.0000`，p95 `6.25 → 9.55 ms`，数据库大小 `344064 → 475136 B`。偏好开启带来约 3.3 ms 的 p95 绝对开销；默认关闭路径由回归测试验证。该基准没有向量模型、并发、真实查询分布或后台 LLM，不能据此推断生产负载的绝对延迟和准确率。

持久 DSH 创造模式会话在完成时的投影计数：4 轮、518 步，`uncachedInputTokens=392776`、`outputTokens=328858`、`cacheReadTokens=226493696`、`cacheWriteTokens=0`。大量计数来自长会话反复读取已缓存上下文，尤其是 Mneme 较大的源码、跨模块审查及有界全量扫描；缓存读取量不等于新生成量，也不能直接换算成费用。未启动子代理，未触发官方 DeepSeek 额度耗尽后的模型切换。重复工作包括早期受沙箱限制的安装和测试启动尝试，以及为确认基线失败所做的扫描；后续改为定向测试并复用同一会话。

## 部署与回滚边界

开发分支将通过独立 PR 交付，保持未合并。生产启用前先对当前 SQLite 做一致性备份，在隔离配置中设置 `apiToken` 和所需功能开关，查看迁移及重复候选；任何规范归并都须人工审阅 dry-run。代码回滚可恢复原插件版本；数据回滚使用启用前的 SQLite 备份。偏好开关关闭后不改变原 importance、遗忘、归档和 scope 规则。

后续真正值得补测的是生产规模下的向量路径、长时间图谱增长和有代表性的真实查询延迟；不得把本次小型合成基准当作这些场景的结论。
