- 原生 **Amadeus 记忆** 设置页新增管理员只读的单场景图谱。场景须明确选择；节点和关系须有该场景未归档、未遗忘的记忆证据。旧的普通图谱读取在严格模式下继续拒绝。
- 隔离 Desktop Plugin Manager 安装 `0.9.5-amadeus.3` 候选包并硬重启后，真实浏览器 GUI 分别选择群 A、群 B 和私聊，逐项显示各自两个节点、一条关系；点击节点可查看详情。发现并修复 SVG 连线 CSS 变量缺失后，重新打包、安装和硬重启，计算样式显示有效描边，连线可见。
- 运行中的 owner API 对三个场景各返回 `2` 个节点、`1` 条关系；未传 scope 返回 `400`、未登录 `401`、跨站来源 `403`、严格模式下普通图谱 `403`。相关边界也有自动测试，覆盖归档/遗忘排除、私聊、节点上限和关系端点保留。
- 图谱快速切换使用请求序号忽略旧响应；节点/关系上限和截断状态明确展示，键盘可使用节点列表。

## 模型侧白名单与双插件实机验收

- Memory 与 QQ 候选包在同一隔离 DSH Desktop 中启用，硬重启后正常加载。QQ 预设启动期工具可见性递归已修复；QQ 全套测试 **281 通过、4 跳过、0 失败**，包含真实 Cordis 4 的服务出现、撤销和同步 `tools/change` 回归。
- 设置最后一级的白名单 GUI 完成了 `qq:group:10001:20001` → `qq:group:10001:20002` 授权；该授权跨硬重启仍存在。测试结束经 owner API 撤销，数据库中不再保留这条合成授权。
- 模型在绑定的合成 QQ Session 中实际调用 `memory_search`：授权时群 A 返回 A+B，群 B 只返回 B，Owner 私聊返回 A+B+私聊；撤销后群 A 立即只返回 A。以上结果来自工具返回内容，未向 QQ 群外发。
- 撤销后群 A 模型直接调用 `memory_get` 读取群 B 的 ID，返回 `memory not found`；调用 `memory_list` 并显式传入群 B 的 `scenes`，返回空列表。模型参数不能扩大服务端授权。
- 群 A 模型实际传入 `mode: "vector"`，真实向量检索只返回本群记录；独立远程 Embedding 探针复用现有 SiliconFlow `Qwen/Qwen3-Embedding-8B` 配置，返回 **4096 维**，一次请求约 **253 ms**。这是单次观测，不代表 P95。
- 群间授权是同 Bot、单向、只读、不可传递，且只作用于长期记忆。Recent/热记忆和模型写入仍限于原 Scene。Memory 缺失或未声明严格 Scene ACL 时，普通 QQ 预设对三个 Memory reader 失败关闭；Owner 保留现有可信私聊能力。

## 仍需区分的边界

- 严格 Scene 模式下，自动摘要已恢复为仅对 QQ Host 可核实的稳定 Session 运行，并在读窗口、模型调用与落库前复核 Scene。autoDream 和 Sleep 仍因跨场景聚合流程缺少安全分区而暂停；这是当前 1.0 的功能取舍，不是环境导致的“无法测试”。
- 旧版完整面板的别名与规范实体管理在存在 Scene 数据时仍被隔离闸门拒绝；新 owner 场景图谱目前只读。正式 1.0 若要求在线别名/合并管理，需要独立的场景安全管理员入口和验收。
- 真实长期聊天的 Recall、MRR 和生产负载 P95 尚无代表性数据。现有合成检索基准与少量隔离 Desktop 请求只能证明测试条件下的行为。
- 生产启用与真实数据迁移尚未执行。上线前应备份 SQLite 和原插件，先在隔离副本上演练迁移及回滚；回滚时需要同时恢复旧包和启用前数据库备份，避免旧版读到不理解的 Scene 数据。

PR #3 只交付候选代码和验收记录，不自动合并或部署。真实长期聊天的检索质量和生产负载 P95 仍需部署前在隔离数据副本上评估。
